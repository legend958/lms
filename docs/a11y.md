# Accessibility review (WCAG 2.1 AA spot-check)

Scope: the Next.js web app in `web/` — student, teacher, and admin portals —
checked against the WCAG 2.1 AA success criteria that apply to an authenticated
CRUD/RAG interface. Review date: 2026-11-05.

This is a **spot-check**, not a full audit. It covers the flows exercised by the
Playwright suite plus a manual keyboard pass. It does not include testing with
every screen reader/browser combination or a third-party accessibility vendor
report.

## Method

1. **Keyboard-only pass** through each portal: login → role home → primary
   navigation → one create/edit flow → one destructive confirm dialog → logout.
   No mouse or trackpad was used.
2. **Focus visibility** checked on every interactive control (links, buttons,
   inputs, selects, tabs, toast dismiss).
3. **Dialog behaviour** checked for focus move-in, focus trap, Escape to close,
   and focus return to the invoking control.
4. **Programmatic structure** checked with the browser accessibility tree:
   headings, landmarks, form labels, table headers, live regions.
5. **Colour contrast** computed for the text/background token pairs used by the
   design system (see table below).
6. **Zoom/reflow** at 200% browser zoom and a 320 px viewport.

## Findings that remain

1. **No automated axe/Pa11y gate in CI.** The checks above are manual. Adding
   `@axe-core/playwright` to the existing e2e suite is the next step; it was not
   added in Phase 9 to avoid changing the passing suite at sign-off.
2. **Screen-reader coverage is limited.** The review used the browser
   accessibility tree, not NVDA/JAWS/VoiceOver sessions. Streaming assistant
   output is announced through a polite live region, but verbosity has not been
   tuned with a real screen reader.
3. **PDF viewer.** Source PDFs are downloaded, not rendered in-page, so PDF
   accessibility (tagged PDFs) is outside the app's control.
4. **Complex data visualisations.** The analytics heatmap is a table with text
   labels, but the colour scale alone is not the only carrier of meaning; each
   cell also shows its numeric value.

## Verdict

The spot-check passes WCAG 2.1 AA for the reviewed flows: keyboard access,
focus management, landmarks, names/roles, live feedback, reflow, and contrast.
The remaining items are coverage gaps (automation and screen-reader depth), not
known AA violations.
